# Candidate Bounded Contexts & Container Mapping

Để quản lý độ phức tạp của hệ thống Superdong, kiến trúc đề xuất chia miền nghiệp vụ thành các **Candidate Bounded Context Proposals** (docs/nghiepvu.md:401-422). 

> [!NOTE]
> **Lưu ý Kiến Trúc**: Phân loại Strategic Domain hiện tại ở trạng thái `BLOCKED_FOR_FINAL_STRATEGIC_CLASSIFICATION` (docs/nghiepvu.md:786). Trong triển khai thực tế của Porto Container Architecture, mã nguồn hiện được tổ chức thành 2 Container nghiệp vụ chính là **`AppSection`** (Hạ tầng, Auth, User, Location) và **`BookingSection`** (Đặt vé, Khóa ghế, Thanh toán, Vé điện tử).

## 👥 Phân Định Actor Nghiệp Vụ & Spatie Global RBAC

![Grug Actor Matrix](/images/grug_actor_matrix.jpeg)

🚨 **LƯU Ý QUAN TRỌNG**: "Actor Nghiệp Vụ" trong tài liệu **KHÔNG ĐỒNG NGHĨA với cột enum `users.role`**. Mã nguồn dự án `E:\cty\superdong-be` **sử dụng Global RBAC từ Package `Spatie\Permission`** với 6 bảng: `users`, `roles`, `permissions`, `model_has_roles`, `role_has_permissions`, `model_has_permissions`. Bảng `users` không chứa cột `role`.

### 📌 Ma Trận Mapping Chuẩn Giữa Khái Niệm Nghiệp Vụ & Codebase

| Khái Niệm Actor | Cách Biểu Diễn Kỹ Thuật Trong Database & Codebase | Quyền Hạn & Giới Hạn An Toàn |
| :--- | :--- | :--- |
| **Khách Vãng Lai (GUEST)** | **Không có bản ghi `users`**. Bản ghi `BOOKING` có `user_id = NULL`. | Đặt vé không cần tài khoản (DEC-026). Thao tác nhạy cảm bằng link bảo mật + OTP (DEC-035). |
| **Khách Tài Khoản (ACCOUNT)** | **User đã đăng ký/đăng nhập** (`user_id != NULL`). Không phải 1 role Spatie. | Xem & quản lý lịch sử Booking do chính mình tạo (DEC-028, DEC-040). |
| **Nhân Viên Quầy** | Spatie Role: **`counter_staff`** (gán qua `model_has_roles`). | Bán vé tại quầy, thu tiền mặt, in vé tại quầy (DEC-006, DEC-008). |
| **Nhân Viên Vận Hành** | Spatie Role: **`operations_staff`** (gán qua `model_has_roles`). | Đổi tàu khác sơ đồ, dời giờ chạy, xử lý chuyến bão hủy (DEC-002, DEC-011). |
| **Soát Vé Cầu Cảng** | Spatie Role: **`checkin_staff`** (gán qua `model_has_roles`). | Quét QR Code check-in. Cấm Check-in Offline trong MVP (DEC-037). |
| **Quản Lý Vận Hành** | Spatie Role: **`manager`** (gán qua `model_has_roles`). | Quyền cao cấp: Override hoàn tiền, sửa check-in nhầm (DEC-034, DEC-036). |
| **Admin Hệ Thống** | Spatie Role: **`admin`** (đã seed sẵn trong hệ thống). | Quản trị toàn bộ Master Data, Users và Cấu hình hệ thống. |

## 🪨 Chi Tiết ERD & Spatie Permission Schema

```mermaid
erDiagram
    USERS ||--o| BOOKINGS : "user_id (NULL if GUEST)"
    USERS ||--|{ MODEL_HAS_ROLES : has
    ROLES ||--|{ MODEL_HAS_ROLES : assigned_to
    ROLES ||--|{ ROLE_HAS_PERMISSIONS : contains
    PERMISSIONS ||--|{ ROLE_HAS_PERMISSIONS : granted_in
    USERS ||--|{ MODEL_HAS_PERMISSIONS : granted_directly

    USERS {
        bigint id PK
        string name
        string email UK
        string phone
    }

    ROLES {
        bigint id PK
        string name "counter_staff / operations_staff / checkin_staff / manager / admin"
        string guard_name "api / web"
    }

    PERMISSIONS {
        bigint id PK
        string name "booking.override / checkin.reverse / refund.approve"
        string guard_name "api / web"
    }

    MODEL_HAS_ROLES {
        bigint role_id FK
        string model_type "AppSection\\User\\Models\\User"
        bigint model_id FK
    }
```

### 🔍 Lý Giải TẠI SAO (Schema Rationale):
- **Vì sao `GUEST` có `user_id = NULL` trong `BOOKINGS`?**: Để giảm tối đa ma sát checkout (DEC-029). Hệ thống không tạo User rác trong DB.
- **Vì sao dùng Spatie RBAC thay vì Cột Enum `role`?**: Giúp linh hoạt gán thêm quyền đặc biệt (`permissions`) cho từng tài khoản mà không cần thay đổi cấu trúc DB.
